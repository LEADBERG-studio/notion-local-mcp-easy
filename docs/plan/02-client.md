# Tunnellio CLI: что делать с клиентом

**Читать после** `00-protocol.md`.

---

## 1. Это переписывание, а не доработка

Прямой ответ на вопрос «доделать или переработать»: **написать заново на Go**, а текущий Python-клиент 0.6.0 оставить жить до перевода всех пользователей.

Почему не патчить существующий:

* **Он про другой протокол.** Сейчас клиент оркестрирует `ssh` и говорит с API Tunnellio. Новый клиент сам является транспортом. Общего кода почти нет, кроме разбора конфига.
* **Питоновский рантайм это половина проблемы.** 9.2 МБ, PyInstaller, распаковка в `%TEMP%` при запуске в onefile. Последнее буквально поведенческая сигнатура дроппера: к «подозрительному туннелю» добавляется «упакованный неизвестный исполняемый файл».
* **Go даёт 3 МБ статики** без рантайма, кросс-сборку под Windows, Linux, macOS и ARM одной командой, и нормальную конкурентность, которая тут нужна на каждом потоке.

Старый клиент **не удаляем**: он остаётся для ssh-контуров, которые никуда не деваются и работают как fallback.

## 2. Интерфейс

```
tunnellio connect --port 8765
tunnellio connect --port 8765 --domain mcp
tunnellio connect --port 8765 --key tk_live_...
tunnellio status
tunnellio doctor
tunnellio version
```

Правила, которые экономят потом много переписки с пользователями:

* **Один обязательный аргумент, `--port`.** Всё остальное имеет разумный дефолт.
* **Ключ берётся из трёх мест по приоритету:** флаг, переменная `TUNNELLIO_API_KEY`, конфиг. Флаг побеждает всегда.
* **Ключ никогда не печатается целиком.** Ни в выводе, ни в логах, ни в ошибках. Только последние 4 символа.
* **Машиночитаемый режим:** `--json` выдаёт по строке JSON на событие. Именно так с клиентом будет разговаривать наш лаунчер, и парсить человеческий текст он не должен.

Вывод при старте короткий и без украшений:

```
Tunnellio 0.7.0
  Local:  http://127.0.0.1:8765
  Public: https://tmp-3515952a.tunnellio.site
  Plan:   free (address changes on every start)
```

## 3. Устройство

```
cmd/tunnellio        разбор аргументов, вывод
internal/config      файл конфигурации, профили
internal/transport   WSS + yamux, реконнект
internal/proxy       поток -> локальный HTTP -> поток
internal/health      счётчики для status
```

### Транспорт

* WSS, заголовки из §4 протокола.
* yamux поверх соединения, ping каждые 30 секунд.
* Реконнект с backoff и джиттером; при `bad_key`, `plan_required`, `protocol_unsupported` **выходим с ненулевым кодом и человеческим текстом**, а не долбимся в стену.
* При обрыве храним `resumeToken` и подставляем его при возврате.

### Проксирование

На каждый входящий поток: разобрать JSON-заголовок, собрать локальный HTTP-запрос, отправить, отдать ответ обратно.

Что обязательно:

* **Потоковое копирование в обе стороны.** Никакого `ReadAll`: SSE от MCP это бесконечное тело, и любая буферизация превращает его в зависание.
* **`http.Transport` с переиспользованием соединений** к локальному сервису и без сжатия со своей стороны: `DisableCompression: true`. Иначе Go сам распакует gzip и потеряет заголовок, а мы уже видели, чем это кончается.
* **Локальный сервис не поднялся** значит отвечаем `502` с внятным текстом, а не роняем туннель.
* **Тайм-аут на локальный запрос настраиваемый**, дефолт большой (300 с), потому что MCP-инструменты бывают долгими.

### Конфигурация

`%LOCALAPPDATA%\Tunnellio\config.json` на Windows, `~/.config/tunnellio/config.json` на остальных.

```json
{
  "version": 1,
  "defaultProfile": "work",
  "profiles": {
    "work": {"port": 8765, "domain": "mcp", "keyRef": "work"}
  }
}
```

**Ключи в этом файле не лежат.** На Windows это Credential Manager, на macOS Keychain, на Linux Secret Service с откатом в файл с правами `0600` и явным предупреждением. Секрет в открытом конфиге рядом с проектом рано или поздно уезжает в git.

## 4. Сборка и поставка

* `CGO_ENABLED=0`, статический бинарь, `-ldflags "-s -w"`.
* Цели: `windows/amd64`, `windows/arm64`, `linux/amd64`, `linux/arm64`, `darwin/arm64`.
* Версия и коммит зашиваются через `-ldflags -X`.
* Артефакты плюс `SHA256SUMS` в релизе GitHub.

**Про антивирус, чтобы не наступить снова:**

* **onedir, а не onefile** это правило для питоновской сборки; для Go вопрос снимается сам.
* **Не паковать UPX.** Упаковщик добавляет ровно ту эвристику, от которой мы уходим.
* **Отправить билд в Microsoft** на разбор ложного срабатывания (WDSI), плюс формы Kaspersky и Dr.Web. Бесплатно, снимает детект за несколько дней.
* **Раздавать через winget, scoop и chocolatey.** Там репутация набирается сама, и пакет вызывает кратно меньше подозрений, чем exe из браузера.
* Сертификат подписи не обязателен: детект был поведенческим на `ssh -R`, а мы от него уходим. Если позже захочется, единственный доступный по географии вариант это Certum Individual CODE, около 139 долларов в год, верификация физлица по документам.

## 5. Что считается готовым

1. Проходят тесты совместимости из `docs/plan/fixtures/`.
2. SSE-поток на 60 секунд живёт, чанки приходят по одному.
3. Обрыв сети на 30 секунд: клиент вернулся сам, адрес тот же.
4. Ответ на 50 МБ проходит, RSS клиента при этом не растёт пропорционально.
5. Каждый код отказа даёт понятный текст и правильный код возврата.
6. `tunnellio doctor` находит: занятый порт, недоступный relay, протухший ключ, отсутствие локального сервиса.
7. Бинарь под Windows запускается на чистой машине без предупреждений SmartScreen о неизвестном издателе сверх обычного для неподписанного файла.
