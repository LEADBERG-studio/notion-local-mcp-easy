# Контур tunnellio_wss в Notion Local MCP Easy

**Читать после** `00-protocol.md`. Это моя часть, здесь всё готово архитектурно: с 2.4.0 каждый режим подключения живёт отдельным изолированным контуром, и новый добавляется по существующему образцу.

---

## 1. Что такое контур

Сейчас их семь: два Serveo, три Tunnellio, sish, свой reverse proxy. Каждый:

* лежит в `connections/circuits/`;
* имеет неизменяемый прообраз в `connections/defaults/*.json`;
* сам решает, какие поля ему нужны, сам валидирует и сам строит команду запуска;
* **не знает о существовании остальных**. Именно это правило спасло нас, когда у Serveo сломался сертификат и один сдохший режим не утащил за собой другие.

Новый контур ничего в этой конструкции не ломает: он просто восьмой.

## 3. Настройки контура

```json
{
  "id": "tunnellio_wss",
  "title": "Tunnellio WSS (443, рекомендуется)",
  "settings": {
    "api_key_env": "",
    "domain": "",
    "relay": "wss://relay.tunnellio.site/connect",
    "client_path": ""
  }
}
```

**Матрица учётных данных**, по образцу существующих контуров:

| Есть ключ | Есть домен | Что происходит |
| --- | --- | --- |
| нет | нет | случайный адрес, каждый запуск новый |
| да | нет | случайный адрес, но со снятыми лимитами |
| да | да | зарезервированный домен |
| нет | да | **отказ на этапе настройки**, а не при запуске |

Последняя строка важна: ошибка конфигурации должна всплывать там, где человек её создаёт, а не через неделю при старте.

Ключ хранится **по имени переменной окружения**, как пароли БД в плагинах. В конфиге лежит имя, а не значение.

## 4. Запуск и разбор

Контур запускает `tunnellio connect --port <port> --json` и читает построчный JSON со стандартного вывода. Из него берутся публичный URL, состояние и ошибки.

Почему `--json`, а не разбор человеческого текста: текст меняется от версии к версии и от локали, и парсер к нему это гарантированные поломки на пустом месте.

Обязательное поведение:

* Клиент **не найден** значит внятная ошибка со ссылкой на установку, а не трассировка стека.
* Клиент **упал** значит контур не переключается молча ни на какой другой. Правило «никакого тихого переключения между контурами» действует и здесь.
* Публичный URL **не появился за 30 секунд** значит показываем последние строки вывода клиента: там будет причина.

## 5. Дефолт для новых областей

Новые рабочие области получают `tunnellio_wss` в качестве стандартного канала. Существующие **не трогаются**: молча переехать на другой транспорт это ровно то, чего мы обещали не делать.

В PROFILES.bat новый контур появляется в общем плоском списке и создаётся как обычный именованный профиль, так что две папки могут пользоваться им с разными доменами.

## 6. Порядок и зависимости

Контур блокируется только клиентом, а не relay: как только у клиента есть `--json` и он умеет подключаться, я могу писать и тестировать контур против чего угодно, хоть против локального relay.

| # | Что | Зависит от |
| --- | --- | --- |
| 1 | Прообраз, контур, регистрация, тесты | ничего, можно начинать сразу |
| 2 | Сбор настроек в SETUP и PROFILES | п.1 |
| 3 | Разбор `--json`, ошибки, диагностика | клиент с `--json` |
| 4 | Живая проверка всех четырёх строк матрицы | relay п.1–6 из `01-relay.md` |
| 5 | Дефолт для новых областей, документация, релиз | п.4 |

## 7. Что считается готовым

1. Все четыре строки матрицы учётных данных проверены живьём.
2. Обрыв сети: контур переживает переподключение клиента, MCP-сессия не рвётся.
3. Крупный gzip-ответ и SSE проходят через туннель без потерь (регресс на 2.4.6 у нас уже есть).
4. `DOCTOR.bat` видит процесс нового клиента и отличает живой туннель от висяка.
5. Ssh-контуры продолжают работать без изменений.
6. Документация обновлена, включая раздел для начинающих.

## Ответ на вопрос о порядке

Последовательность «сначала сервер, потом клиент, потом контур» верна **не полностью**, и это важно.

Первым идёт **не сервер, а протокол** (`00-protocol.md`). Как только он заморожен, **сервер и клиент делаются параллельно**: они разговаривают через контракт, а не друг через друга. Ждать готового relay, чтобы начать клиента, значит потерять недели впустую.

Контур подключается к клиенту, а не к relay, поэтому его можно начинать почти сразу и заканчивать последним.

Практически: утверждаем протокол → Caddy с wildcard (это блокер по срокам, потому что зависит от DNS-провайдера) → relay и клиент параллельно → стыковка → контур → квоты, консоль, пакетные менеджеры.
