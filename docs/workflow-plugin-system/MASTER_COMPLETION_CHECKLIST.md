# Master Completion Checklist

Этот документ задаёт жёсткое правило завершения инициативы.

## Главное правило

Инициатива **не считается завершённой**, пока одновременно не выполнено всё ниже:

1. `TASK-001` ... `TASK-014` имеют статус `DONE`.
2. Нет задач со статусом `ACTIVE` или `BLOCKED`.
3. Нет промежуточных пометок вида `checkpoint`, `baseline`, `partial`, которые подаются как финальный результат.
4. Пройден обязательный verification path до `V4`.
5. Существует release-candidate пакет документации и кода.
6. Есть финальный handoff с явной сводкой по всем task ids.

## Что НЕ считается завершением

Следующее **не является** завершением инициативы:

- выполнен только foundation;
- выполнен только baseline plugin;
- закрыты только Milestone 1-3;
- есть handoff с формулировкой `resume later`;
- есть только частичная тестовая матрица;
- есть только SQLite baseline без завершения TASK-010 ... TASK-014.

## Обязательная финальная сводка

Перед тем как объявить работу завершённой, исполнитель обязан показать таблицу:

- task id
- status
- code outputs
- test evidence
- remaining blockers

Если хотя бы у одного task нет статуса `DONE`, инициатива остаётся незавершённой.

## Правило scope

Исполнитель не имеет права самостоятельно сужать scope до milestone/checkpoint/baseline без явного отдельного разрешения пользователя.

## Правило release readiness

Фраза `готово к релизу`, `release candidate` или эквивалент допустима только если:

- завершён `TASK-014`;
- обновлены README / release docs / known limitations;
- пройдены требуемые тесты и миграционные проверки;
- в финальной сводке нет открытых blocker-ов.
