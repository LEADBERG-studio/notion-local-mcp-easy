# Workflow Profiles + Plugin System

Эта папка содержит отдельный пакет документации по развитию текущей схемы `PATH[N]` **на её основе**, а не вместо неё: сохранённые пути остаются стартовой точкой, но вокруг них добавляется модель **workflow profiles**, явное окружение и **универсальная plugin-system**.

## Что находится в этой папке

- `EXECUTION_PROTOCOL.md` — правило одного активного TODO, порядок остановки и возобновления работ.
- `HANDOFF_TEMPLATE.md` — единый handoff-пакет между задачами и сессиями.
- `VERIFICATION_LEVELS.md` — уровни проверки от документного ревью до release candidate.
- `PLUGIN_REGISTRATION_CONTRACT.md` — универсальный контракт регистрации инструментов плагинов.
- `AI_PLUGIN_AUTHORING_PROMPT.md` — подробный суперпромт для генерации совместимых плагинов.
- `RELEASE_PATH.md` — путь от проектирования до релиза.
- `MASTER_COMPLETION_CHECKLIST.md` — жёсткий критерий, когда инициативу действительно можно считать завершённой.
- `tasks/` — пошаговые задания. Каждое задание — отдельный завершённый этап.

## Главная архитектурная идея

Сохранённая рабочая область по-прежнему опирается на `PATH[N]`, но теперь каждый такой путь должен разворачиваться в **workflow profile**.

Базовый профиль включает:

- `pathSlot` / ссылку на `PATH[N]`
- `workspacePath`
- `accessMode`
- `environmentMode = DEFAULT | CUSTOM`
- profile-specific environment state
- plugin-specific overrides
- metadata и diagnostics

### Что означает выбор пути

Когда пользователь выбирает путь, он фактически выбирает сразу:

1. рабочую область;
2. режим доступа;
3. конфигурацию окружения для этой области.

### Что означает DEFAULT для области

Для конкретной области окружение считается `DEFAULT`, пока одновременно не произошло следующее:

- к области не был подключён хотя бы один плагин;
- для этого плагина не были сохранены настройки именно для этой области.

До этого момента профиль использует базовую конфигурацию без area-specific plugin state.

### Как подключаются плагины

Подключение плагина должно рассматриваться как управляемое действие пользователя:

- плагин подключается запуском его **исполняемого файла / entrypoint**;
- при подключении пользователь выбирает, куда его привязать:
	- в **текущую конфигурацию области**;
	- или **глобально**;
- после этого профиль области либо остаётся в `DEFAULT`, либо переходит в `CUSTOM`, если для данной области были сохранены plugin-specific настройки.

Переключение рабочей области должно активировать **весь профиль**, а не только путь.

## Что обязательно должно получиться

1. Модель workflow profile, построенная **на основе** существующих `PATH[N]`.
2. Выбор пути, который активирует workspace, access mode и environment config.
3. Ясная семантика `DEFAULT/CUSTOM` для каждой области.
4. Универсальная система регистрации plugin tools.
5. Поддержка семейств плагинов для нескольких БД.
6. Основа для внешних нейросетей и субагентов.
7. Настолько подробная authoring-документация и промт, чтобы пользователь мог дать задачу другой нейросети и получить совместимый плагин.

## Как работать по этим документам

1. Открыть `EXECUTION_PROTOCOL.md`.
2. Держать **ровно одно** задание в статусе `ACTIVE`.
3. Выполнять задачи по очереди из папки `tasks/`.
4. Перед любой паузой заполнять `HANDOFF_TEMPLATE.md`.
5. Перед закрытием задачи проходить нужный verification level.
6. Перед объявлением инициативы завершённой пройти `MASTER_COMPLETION_CHECKLIST.md`.
