Tunnellio: постоянный публичный доступ

Tunnellio — управляемый сервис публикации локального MCP-сервера в интернет. Для пользователя это кабинет, API, постоянный публичный адрес вида https://имя.tunnellio.site, CLI-клиент и отдельный OAuth-контур на стороне Tunnellio.

Важно: эта страница описывает пользовательскую настройку и клиентское использование Tunnellio. Внутренние детали реализации сервиса здесь намеренно не публикуются.

Адреса сервиса

ЧтоАдресДля чего
Кабинет Tunnellio https://console.tunnellio.ru Вход, управление подключениями, токенами, доменами, OAuth-приложениями и параметрами доступа.
API-документация https://api.tunnellio.ru/docs Официальная справка по API Tunnellio.
Публичные адреса туннелей https://*.tunnellio.site Итоговый HTTPS-адрес вашего опубликованного Local MCP Easy.

Не путайте четыре уровня доступа

В связке Local MCP Easy + Tunnellio есть несколько разных сущностей. Они похожи по названию, но используются в разных местах.

УровеньГде используетсяЧто вводить пользователю
Bearer token Local MCP Easy Когда MCP-клиент подключается к Local MCP Easy в legacy/dual режиме. Строку из запуска сервера: Authorization=Bearer <token> (Bearer token).
OAuth Local MCP Easy Если сам Local MCP Easy выступает OAuth-сервером для MCP-клиента. Данные, которые выдаются через OAUTH_SETUP.bat и REGISTER_OAUTH_CLIENT.bat.
Tunnellio API token Для CLI-клиента и автоматизации, которые обращаются к API Tunnellio. Токен из кабинета Tunnellio. В API он передаётся как Authorization: Bearer <Tunnellio API token>.
Tunnellio OAuth Когда доступ к опубликованному адресу защищается OAuth-контуром Tunnellio. OAuth-приложение, redirect URI, scopes и client credentials из кабинета Tunnellio.

Что настроить в кабинете Tunnellio

Откройте https://console.tunnellio.ru. В интерфейсе вам нужны не технические детали сервиса, а прикладные настройки вашего подключения.

  1. Создайте или выберите подключение

    Подключение — это связка локального сервера, публичного адреса и правил доступа. Для Local MCP Easy обычно нужен постоянный адрес.

  2. Выберите имя публичного адреса

    Итоговый URL будет в зоне https://*.tunnellio.site, например https://my-mcp.tunnellio.site. В документации не используйте временные example-домены — ориентируйтесь на реальную зону сервиса.

  3. Укажите локальную цель

    Это адрес, куда Tunnellio-клиент будет отправлять входящий трафик на вашей машине. Для Local MCP Easy это обычно 127.0.0.1 и порт, показанный при запуске сервера.

  4. Выберите режим авторизации

    Если доступ должен проверять Tunnellio, выберите OAuth на стороне Tunnellio. Если клиент работает напрямую с Local MCP Easy bearer/OAuth, оставьте соответствующий режим Local MCP Easy и не смешивайте токены.

  5. Сохраните значения для клиента

    Вам понадобятся: публичный URL, Tunnellio API token для CLI, а при OAuth — client id, redirect URI, scopes и, если применимо, client secret.

Постоянное подключение Local MCP Easy через Tunnellio

  1. Запустите Local MCP Easy локально

    Запустите START.bat и дождитесь строки с локальным адресом и авторизацией. Если клиент просит bearer header, используйте формат Authorization=Bearer <token> (Bearer token).

  2. Подготовьте подключение в Tunnellio

    В кабинете https://console.tunnellio.ru создайте постоянное подключение в зоне https://*.tunnellio.site и укажите локальный порт Local MCP Easy.

  3. Запустите Tunnellio CLI

    tunnellio connect --run --watch --name notion-mcp

    Ключ --watch нужен, чтобы клиент следил за процессом и поднимал соединение повторно при сбоях.

  4. Получите итоговые параметры

    tunnellio show-config --name notion-mcp

    Используйте полученный публичный URL в MCP-клиенте. Для постоянных подключений это будет адрес в зоне https://*.tunnellio.site.

  5. Проверьте состояние

    tunnellio status
tunnellio status --name notion-mcp

OAuth на стороне Tunnellio

Tunnellio может быть отдельным OAuth-слоем перед опубликованным MCP endpoint. Это удобно, когда нужен постоянный публичный URL и централизованное управление доступом в кабинете.

Что подготовить

  • Публичный адрес в зоне https://*.tunnellio.site.
  • OAuth-приложение в кабинете Tunnellio.
  • Redirect URI, который ожидает ваш клиент.
  • Нужные scopes, например proxy.connect, proxy.inspect, mcp.read, mcp.write.
  • Client id и, если выбран confidential client, client secret.

Discovery и metadata

Если клиент умеет OAuth discovery, используйте metadata Tunnellio. Точные URL и параметры смотрите в API-документации: https://api.tunnellio.ru/docs.

/.well-known/oauth-authorization-server
/.well-known/oauth-protected-resource

CLI-команды

tunnellio oauth-login --token-name notion-mcp --use-discovery --enable-pkce
tunnellio oauth-refresh --token-name notion-mcp
tunnellio oauth-introspect --token-name notion-mcp
Подсказка: OAuth Tunnellio и OAuth Local MCP Easy — разные контуры. Если сомневаетесь, выберите один главный слой авторизации и не включайте два OAuth одновременно без необходимости.

API Tunnellio

Для автоматизации используйте официальную API-документацию: https://api.tunnellio.ru/docs.

Авторизация API:

Authorization: Bearer <Tunnellio API token>

На уровне пользователя обычно нужны группы операций:

  • metadata — узнать параметры сервиса и доступные возможности;
  • keys / credentials — подготовить клиентский доступ;
  • domains / public URLs — управлять постоянными адресами в зоне https://*.tunnellio.site;
  • launch / connection profile — получить параметры запуска клиента;
  • sessions — отслеживать активное подключение, heartbeat, resume и закрытие.

Не копируйте API token в публичные issue, README, скриншоты или PromptQL-артефакты.

Tunnellio CLI-клиент

CLI-клиент нужен, чтобы не собирать параметры подключения вручную. Он получает настройки из Tunnellio, запускает соединение, следит за ним и сохраняет runtime snapshot.

Основные команды

tunnellio connect --run --watch --name notion-mcp
tunnellio show-config --name notion-mcp
tunnellio status
tunnellio status --name notion-mcp
tunnellio stop --name notion-mcp
tunnellio stop --all

Что хранить у себя

  • имя подключения, например notion-mcp;
  • публичный URL в зоне https://*.tunnellio.site;
  • локальный порт Local MCP Easy;
  • Tunnellio API token — только в защищённом локальном хранилище;
  • OAuth token record, если используется OAuth Tunnellio.

Рецепты

Хочу просто постоянный MCP URL

  1. Запустите Local MCP Easy через START.bat.
  2. Создайте подключение в console.tunnellio.ru.
  3. Запустите tunnellio connect --run --watch --name notion-mcp.
  4. Возьмите URL через tunnellio show-config --name notion-mcp.
  5. Вставьте URL в MCP-клиент.

Хочу OAuth на уровне Tunnellio

  1. Создайте постоянный публичный адрес в зоне https://*.tunnellio.site.
  2. В кабинете создайте OAuth-приложение и укажите redirect URI клиента.
  3. Выберите scopes.
  4. Настройте клиент на discovery/metadata Tunnellio.
  5. Проверьте login, refresh и introspect через CLI или клиент.

Типичные ошибки

  • Клиент просит bearer, а вы вводите Tunnellio API token. Это разные токены. Bearer Local MCP Easy берите из окна запуска сервера.
  • OAuth redirect URI не совпадает. В кабинете Tunnellio должен быть ровно тот redirect URI, который использует клиент.
  • Неясно, какой URL вставлять в MCP-клиент. Используйте результат tunnellio show-config --name ..., а не придумывайте адрес вручную.
  • После перезапуска клиент не подключается. Проверьте tunnellio status --name ..., затем перезапустите supervised connection.
  • Два OAuth-контура одновременно. Для начала выберите один: OAuth Tunnellio или OAuth Local MCP Easy.

Если меняете публичный URL, auth mode или OAuth-настройки, после этого перезапустите сервер и заново проверьте подключение клиента.
