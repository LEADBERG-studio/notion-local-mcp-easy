Коротко: что такое Tunnellio

Tunnellio публикует локальный MCP/web-сервер в интернет через ваш VPS и ваши домены. В отличие от временного туннеля, Tunnellio даёт управляемый контур:

  • сервер LEADBERG-studio/tunnellio: web-кабинет, API, OAuth, SSH reverse tunnel, домены, ключи, сессии;
  • клиент LEADBERG-studio/tunnellio-api-client: CLI/бинарник, который ходит в API, строит launch spec, запускает SSH, следит за туннелем и сохраняет runtime snapshot;
  • постоянный URL: например https://mcp.tunnel.example.net/mcp, который можно вписать в Notion/MCP-клиент;
  • server-side OAuth: OAuth-контур на стороне Tunnellio для proxy/MCP-доступа, discovery endpoints, refresh tokens и introspection.

Local MCP Easy при этом остаётся локальным MCP-сервером на вашей машине. Tunnellio - внешний слой публикации и управления доступом.

Три разных токена и два OAuth-контура

Новичкам легко запутаться, потому что здесь несколько уровней авторизации. Их важно не смешивать.

ЧтоГде живётДля чего нужно
Authorization=Bearer <token> (Bearer token) Local MCP Easy config.json Local MCP Easy Прямой bearer-доступ к вашему локальному MCP endpoint, если клиент работает в legacy/dual режиме.
OAuth Local MCP Easy Local MCP Easy: OAUTH_SETUP.bat, REGISTER_OAUTH_CLIENT.bat, oauth_state.json OAuth 2.1 непосредственно на MCP-сервере Local MCP Easy.
Tunnellio API token Web-кабинет Tunnellio / API tokens Клиент tunnellio.exe использует его как Authorization: Bearer ... для POST-only API.
Tunnellio server-side OAuth Сервер Tunnellio: OAuth apps, redirect URI, scopes, client secret OAuth-контур на уровне proxy/cloud-публикации: proxy.connect, proxy.inspect, mcp.read, mcp.write, mcp.admin.

Практическое правило: сначала решите, кто должен проверять пользователя: сам Local MCP Easy или Tunnellio перед ним. Для постоянного облачного URL обычно полезен Tunnellio-контур, а Local MCP Easy можно оставить в совместимом legacy/dual режиме.

Сервер Tunnellio: что нужно поднять

Серверный репозиторий: github.com/LEADBERG-studio/tunnellio.

Компоненты

  • sish - SSH-сервер для reverse tunnel;
  • Caddy - TLS и маршрутизация HTTPS;
  • Flask - web-кабинет и API;
  • SQLite - резервации, SSH-ключи, OAuth apps, redirect URI, scopes, client secret;
  • Docker Compose - запуск стека.

Домены

  • SITE_DOMAIN - web-кабинет, например hub.example.com;
  • API_DOMAIN - HTTP API, например api.example.com;
  • TUNNEL_DOMAIN - домен туннелей, например tunnel.example.net;
  • *.TUNNEL_DOMAIN - wildcard-запись для публичных поддоменов.

Текущий серверный контур рассчитан на Cloudflare DNS, чтобы Caddy мог выпускать сертификаты через DNS challenge.

Bootstrap

На VPS выполняется bootstrap-команда из README Tunnellio. В ней вы передаёте домены, Cloudflare token, admin password и target dir. Важная гарантия: при штатном update/reinstall каталог /opt/tunnellio/data сохраняется. В нём лежат резервации, ключи, OAuth apps, redirect URI, scopes и client secret.

bash bootstrap.sh \
  --site-domain hub.example.com \
  --api-domain api.example.com \
  --tunnel-domain tunnel.example.net \
  --acme-email ops@example.com \
  --cloudflare-token YOUR_CLOUDFLARE_API_TOKEN \
  --admin-password "длинный-пароль" \
  --target-dir /opt/tunnellio

Что сделать в web-кабинете Tunnellio

  1. Откройте https://SITE_DOMAIN и войдите с admin password.
  2. Создайте или проверьте API token для CLI/интеграций.
  3. Добавьте SSH public key машины, где запускается Local MCP Easy.
  4. Создайте постоянный домен, например mcp, чтобы получить https://mcp.TUNNEL_DOMAIN.
  5. Укажите локальную цель: обычно 127.0.0.1 и порт, на котором слушает Local MCP Easy.
  6. Если нужен OAuth на стороне Tunnellio, поставьте authMode=oauth и включите требование стабильного URL (stableUrlRequired).
  7. Создайте OAuth app: redirect URI, scopes, client_id, при необходимости client_secret для confidential client.

Для OAuth-домена постоянный URL принципиален: OAuth redirect URI и issuer/discovery должны быть стабильными.

Tunnellio OAuth: endpoints и scopes

Tunnellio публикует OAuth metadata и protected-resource metadata. Клиент может загружать их автоматически.

EndpointНазначение
GET /.well-known/oauth-authorization-serverOAuth discovery metadata.
GET /.well-known/oauth-protected-resourceMetadata защищённого ресурса.
POST /oauth/authorizeAuthorization Code flow.
POST /oauth/tokenПолучение/refresh token.
POST /oauth/introspectПроверка access token.
POST /oauth/clients/registerDynamic client registration, если включён на сервере.

Поддерживаются grant types authorization_code и refresh_token, PKCE S256, token auth methods none и client_secret_post.

Основные scopes: mcp.read, mcp.write, mcp.admin, proxy.connect, proxy.inspect.

Это отдельный контур от OAuth Local MCP Easy. Его настраивают на сервере Tunnellio в OAuth apps.

Tunnellio Integration API

API работает через Authorization: Bearer <Tunnellio API token> и в основном использует POST-only endpoints.

Meta

  • POST /v1/meta - API metadata: домены, SSH host/port/user, install URLs, OAuth metadata.
  • POST /v1/capabilities - лимиты и feature flags для ключей, доменов и ephemeral-сессий.
  • GET /healthz, GET /readyz - liveness/readiness.

Keys

  • POST /v1/keys, /list, /get, /update, /delete - управление SSH public keys.

Domains

  • POST /v1/domains - создать постоянный домен;
  • POST /v1/domains/list, /check, /get, /update, /delete - управление доменами;
  • POST /v1/domains/connection-profile - получить готовый SSH connection profile для домена.

Sessions

  • POST /v1/sessions/ephemeral - временный случайный домен;
  • POST /v1/sessions/open - открыть session protocol v1;
  • POST /v1/sessions/heartbeat - heartbeat активной сессии;
  • POST /v1/sessions/resume - resume ранее открытой сессии;
  • POST /v1/sessions/close - закрыть сессию;
  • POST /v1/sessions/status - статус;
  • POST /v1/sessions/complete - graceful completion ephemeral-сессии.

Launch spec

POST /v1/launch-spec - orchestration endpoint. Он позволяет за один запрос использовать существующий домен/ключ или создать недостающие ресурсы и получить готовые параметры запуска.

Tunnellio API client: что умеет

Клиентский репозиторий: github.com/LEADBERG-studio/tunnellio-api-client.

Клиент - это CLI/helper поверх Tunnellio API и системного OpenSSH. Он нужен, чтобы приложение не собирало SSH-команду вручную.

  • Bearer auth к POST-only API;
  • orchestration через POST /v1/launch-spec;
  • запуск SSH через connect --run;
  • supervised mode через connect --run --watch;
  • session-aware lifecycle: open -> heartbeat -> resume -> close;
  • получение runtime config / connection params через show-config --name;
  • OAuth discovery, protected-resource metadata, Authorization Code + PKCE flow;
  • команды oauth-login, oauth-refresh, oauth-introspect;
  • локальное хранение token record: accessToken, refreshToken, scopes, issuer, endpoints, привязка к client/domain.

Пример постоянного туннеля

.\tunnellio.exe --token YOUR_TOKEN connect ^
  --domain existing:mcp ^
  --local-port 3000 ^
  --run ^
  --watch ^
  --name notion-mcp ^
  --health-path / ^
  --log-file .\logs\tunnel.log

После запуска можно получить итоговые параметры:

.\tunnellio.exe show-config --name notion-mcp

Это особенно важно для random/ephemeral-доменов: приложение не угадывает итоговый hostname, а читает его после запуска.

Управление

.\tunnellio.exe status
.\tunnellio.exe status --name notion-mcp
.\tunnellio.exe stop --name notion-mcp
.\tunnellio.exe stop --all

OAuth-команды клиента

.\tunnellio.exe --token YOUR_TOKEN oauth-login ^
  --domain existing:mcp ^
  --client-id YOUR_CLIENT_ID ^
  --redirect-uri http://localhost:3333/callback ^
  --scopes "proxy.connect proxy.inspect" ^
  --token-name notion-mcp ^
  --use-discovery ^
  --enable-pkce

.\tunnellio.exe --token YOUR_TOKEN oauth-refresh --token-name notion-mcp
.\tunnellio.exe --token YOUR_TOKEN oauth-introspect --token-name notion-mcp

Сценарий: Local MCP Easy через Tunnellio с постоянным URL

  1. Запустите Local MCP Easy локально и убедитесь, что он слушает 127.0.0.1:<PORT>.
  2. На сервере Tunnellio создайте постоянный домен, например mcp.
  3. Привяжите к домену SSH key вашей машины.
  4. Если нужен OAuth на стороне Tunnellio, включите authMode=oauth и stableUrlRequired, затем создайте OAuth app.
  5. На машине с Local MCP Easy запустите tunnellio.exe connect --run --watch --name notion-mcp.
  6. Проверьте tunnellio.exe show-config --name notion-mcp и найдите публичный URL.
  7. В MCP-клиенте используйте https://mcp.TUNNEL_DOMAIN/mcp или URL из show-config.
  8. Если клиент просит bearer header Local MCP Easy, используйте строку из запуска сервера: Authorization=Bearer <token> (Bearer token).
  9. Если клиент работает через Tunnellio OAuth, используйте Tunnellio discovery URL и OAuth app credentials.

Типичные ошибки

  • OAuth не работает на случайном URL. Для OAuth нужен стабильный public URL и корректный redirect URI.
  • Путаются API token и MCP bearer token. Tunnellio API token нужен CLI/серверному API; Local MCP bearer token нужен MCP-клиенту, если он идёт напрямую в MCP endpoint.
  • Туннель поднялся, но клиент не знает URL. Используйте show-config --name, особенно для random/ephemeral-доменов.
  • После reconnect меняется состояние. Для постоянного режима используйте persistent domain, session lifecycle и supervised --watch.
  • Удалили /opt/tunnellio/data. Это потеря резерваций, ключей, OAuth apps и secrets. Обновляйте через штатный reinstall/update-flow.
