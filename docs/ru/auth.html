Главное правило

Не публикуйте токены, owner code, client secret и локальные config-файлы.

Авторизация: какой режим выбрать

РежимЧто значитКогда выбирать
legacyОдин статический Authorization=Bearer <token> (Bearer token)Notion Custom MCP или клиент, который просит просто URL + token.
oauthТолько OAuth 2.1Клиент умеет OAuth MCP flow и не принимает статический токен.
dualAuthorization=Bearer <token> (Bearer token) и OAuth на одном /mcpПереходный период: часть клиентов старая, часть OAuth.

Authorization=Bearer <token> (Bearer token) простыми словами

Сервер генерирует секретный токен. Клиент отправляет заголовок:

Authorization: Bearer ВАШ_ТОКЕН

Это проще всего, но если клиент требует OAuth — этот режим не подойдёт.

OAuth простыми словами

OAuth — это способ, при котором MCP-клиент регистрируется как приложение и получает access token через стандартный flow. В этом проекте сервер сам предоставляет OAuth endpoints.

Scopes

ScopeЧто разрешает
mcp.readЧтение файлов/данных.
mcp.writeИзменение файлов.
mcp.commands.runЗапуск разрешённых команд в trusted developer mode.
mcp.gitGit-операции, если включён developer mode и repo context.
mcp.adminАдминистративные действия. Не выдавайте без необходимости.
Новичку: для обычной работы начинайте с mcp.read mcp.write. Добавляйте команды/git/admin только если понимаете зачем.

Что править вручную

Обычно ничего вручную править не нужно: используйте OAUTH_SETUP.bat, REGISTER_OAUTH_CLIENT.bat и SHOW_CONNECTION.bat. Если всё-таки редактируете config, файл здесь:

%LOCALAPPDATA%\NotionMcpEasy\config.json

Ключевые поля: auth_mode, token, oauth_owner_code, public_url, tunnel_backend, serveo_hostname, tunnellio_domain, tunnel_host, *.tunnellio.site.
