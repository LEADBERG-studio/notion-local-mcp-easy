Главное правило

Не публикуйте токены, owner code, client secret и локальные config-файлы.

IDE Gateway: мост между IDE и моделью

ide_gateway даёт IDE OpenAI-compatible API, но сам сервер живёт в песочнице модели. После однократной настройки обычная команда ровно одна: «подними мост».

Коротко: модель сама получает installer-промт, находит внутренний endpoint, key и точные модели своей песочницы, запускает одну команду и возвращает готовые настройки IDE. Пользователь не должен искать внутренние ключи.

Схема без магии

IDE → https://<hostname>.tunnellio.site/v1
    → keyless Tunnellio TCP bridge
    → resident server в песочнице модели
    → внутренний LLM egress этой же песочницы

SSH-туннеля здесь нет: не нужны SSH-ключи, регистрация public key или облачный API token в sandbox-клиенте.

Настройка для чайников

  1. Включите trusted developer mode.
    В корне проекта запустите SETUP.bat для нужной рабочей области.
  2. Настройте плагин.
    Запустите plugins\ide_gateway\SETUP.bat. Выберите current, full_access, sandbox, для первой проверки ephemeral.
  3. Перезапустите MCP.
    STOP.bat, затем START.bat.
  4. Напишите модели «подними мост».
    Она должна вызвать ide_gateway_bridge_prompt и выполнить полученную команду в собственной Linux-песочнице, не через Windows MCP host.
  5. Скопируйте три значения.
    Публичный base_url, ключ ideg_... и точный model ID.
  6. Добавьте OpenAI-compatible provider в IDE.
    Сохраните эти три значения и отправьте короткий тестовый запрос.

Что вставлять в IDE

ПолеЗначение
Base URLhttps://<hostname>.tunnellio.site/v1
API keyideg_... из итогового ответа модели
Modelточный ID, возвращённый публичным /v1/models
Не путайте URL: внутренний endpoint песочницы никогда не вставляется в IDE и не публикуется в чате. IDE использует только public Tunnellio URL.

Что делает installer

  • пишет защищённый config в ~/.ide_gateway, не печатая внутренние секреты;
  • поднимает detached OpenAI-compatible server и TCP bridge, не привязанные к короткому tool-call;
  • работает с OpenAI- и Anthropic-style upstream;
  • показывает реальные model IDs песочницы;
  • переподключает bridge и повторно использует живой hostname;
  • оставляет только пять последних логов;
  • не убивает процессы из-за временного 404/502/504 при propagation.

Резервный промт

Если модель не поняла короткую команду, полезла в Windows-пути или просит у вас внутренний key, откройте отдельный файл docs/ru/IDE_GATEWAY_FALLBACK_PROMPT.md и скопируйте промт целиком.

Подними IDE Gateway в СВОЕЙ модельной песочнице.
Вызови ide_gateway_bridge_prompt с include_secret=true.
Не используй Local MCP/run_program или Windows-пути.
Не печатай внутренний endpoint/key.
Проверь status, public /health и /v1/models.

Проверка и ремонт

python3 ~/.ide_gateway/sandbox_installer.py status
python3 ~/.ide_gateway/sandbox_installer.py repair
python3 ~/.ide_gateway/sandbox_installer.py stop

install и repair идемпотентны. Не запускайте несколько install одновременно. stop нужен только для намеренного выключения.

Типовые проблемы

СимптомЧто делать
Public URL даёт 404/502/504Проверьте status. Если server и bridge живы, подождите propagation и повторите запрос, не перезапуская всё.
Модель просит внутренний API keyЭто ошибка сценария. Используйте резервный промт: модель должна получить key из собственной runtime-среды.
В /v1/models alias вместо реальных моделейЗапустите repair с точными model IDs песочницы; не выдумывайте имена.
Процесс умер после tool-callУбедитесь, что используется installer 2.3.0, затем repair. Он запускает detached resident-процессы.
Hostname истёкrepair создаст новый ephemeral route. Обновите Base URL в IDE.

Не путайте с IDE Bridge

ide_bridge является отдельным queue/poll fallback с портом 8797 и ключом ideb_.... Он не нужен для нормального прямого sandbox TCP bridge.
