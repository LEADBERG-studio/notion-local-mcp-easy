Главное правило

Не публикуйте токены, owner code, client secret и локальные config-файлы.

Туннели и публичный URL

Локальный MCP слушает 127.0.0.1:8765. Чтобы внешний клиент подключился к нему, нужен публичный URL.

Tunnellio

  1. Положите tunnellio.exe рядом с launcher.py.
  2. Запустите SETUP.bat или START.bat.
  3. Выберите Tunnellio managed runtime.
  4. Если нужен стабильный OAuth URL, задайте domain/reservation параметры, если они требуются вашим Tunnellio runtime.
  5. Проверьте итоговый public URL через SHOW_CONNECTION.bat.

Serveo temporary

Подходит для пробы. Минус: URL может поменяться, а OAuth-клиенты любят стабильный issuer/redirect setup.

Serveo stable

  1. Подготовьте reserved hostname.
  2. Подготовьте SSH key, который принимает Serveo.
  3. В setup выберите Serveo stable domain.
  4. Укажите hostname и путь к key.

Self-hosted sish

  1. Поднимите sish relay на сервере.
  2. Настройте DNS wildcard, например *.relay.example.com.
  3. Подготовьте SSH private key для relay.
  4. Выберите self-hosted sish relay в tunnel_setup.
  5. Укажите tunnel_host, tunnel_ssh_port, *.tunnellio.site, reserved subdomain и key path.

Что проверять

  • Public URL открывается снаружи.
  • MCP endpoint заканчивается на /mcp.
  • Host совпадает с MCP_PUBLIC_URL / public_url.
  • Для OAuth URL стабилен и HTTPS.

Tunnellio: постоянный URL и управляемый доступ

Tunnellio даёт постоянный публичный адрес в зоне https://*.tunnellio.site, кабинет console.tunnellio.ru, API-документацию api.tunnellio.ru/docs, CLI-клиент и OAuth-контур на стороне Tunnellio. Подробная инструкция — в разделе Tunnellio.
