Главное правило

Не публикуйте IDE keys и runtime state.

IDE Bridge — отдельный poll/queue мост

ide_bridge — это отдельный плагин для старого режима, где IDE-запросы кладутся в очередь, а активная модель сама опрашивает её через bridge_step.py poll.

Когда выбирать: используйте ide_bridge, если хотите, чтобы именно модель в MCP-чате обрабатывала IDE-запросы своими tools. Для прямого sandbox-сервера через Tunnellio TCP bridge используйте IDE Gateway.

Быстрый старт

  1. Откройте plugins\ide_bridge и запустите SETUP.bat.
  2. Выберите current, full_access, оставьте default port 8797.
  3. Перезапустите MCP, чтобы endpoint поднялся.
  4. Вызовите ide_bridge_show_config с include_secret=true и скопируйте настройки в IDE.
  5. Вызовите ide_bridge_bridge_prompt и используйте его как системный prompt для модели.
  6. Модель запускает короткий loop: bridge_step.py poll --timeout 3, обрабатывает запрос, затем complete.

Важно: этот режим живёт, пока модель крутит poll loop. Не используйте его как долгий MCP tool-call: prompt специально заставляет делать короткие run_program итерации.
