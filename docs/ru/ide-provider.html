Главное правило

Не публикуйте токены, owner code, client secret и локальные config-файлы.

IDE Provider: подключить IDE как OpenAI-compatible клиента

ide_provider — это active-bridge плагин. Он поднимает локальный OpenAI-compatible endpoint на 127.0.0.1, принимает запросы от IDE и передаёт их активной MCP-модели через очередь.

Для новичка: включайте этот плагин только в trusted developer mode и только для IDE/клиентов, которым доверяете. Endpoint локальный, но он даёт IDE канал общения с активной MCP-моделью.
Responder-loop обязателен: ide_provider_start поднимает только HTTP endpoint. Чтобы IDE получила осмысленный ответ, активная MCP-модель должна постоянно выполнять цикл ide_provider_wait_request - ide_provider_send_response. Без этого запросы будут висеть в очереди или истекать по timeout.

Зачем это нужно

Некоторые IDE умеют работать с OpenAI-compatible chat completions API, но не умеют напрямую позвать активную MCP-модель в вашем чате. ide_provider делает мост:

IDE → http://127.0.0.1:<port>/v1/chat/completions
    → очередь ide_provider
    → ide_provider_wait_request
    → MCP-модель думает и использует tools
    → ide_provider_send_response
    → IDE получает ответ

Как включить

  1. Запустите рабочую область в trusted developer mode.
    В file-only режиме tools start, stop и rotate_token недоступны.
  2. Откройте папку плагина.
    Перейдите в plugins\ide_provider.
  3. Запустите SETUP.bat или ENABLE.bat.
    Выберите current для текущей рабочей области или global для всех областей. Обычно для IDE выбирают current.
  4. Выберите full_access.
    Он нужен для запуска/остановки локального endpoint и ротации token.
  5. Оставьте default endpoint settings.
    Setup автоматически сгенерирует локальный API key, а endpoint по умолчанию слушает только 127.0.0.1.
  6. Перезапустите MCP.
    После enable/disable registry tools пересобирается при рестарте.
  7. Запустите endpoint через MCP tool.
    Например: ide_provider_start с name="ide" и model_id="ide-provider".
  8. Скопируйте настройки в IDE.
    Используйте base_url, api_key и model, которые вернул ide_provider_start или ide_provider_show_config.

Как работает запрос

  1. IDE отправляет chat completion request.
  2. Worker кладёт request в file-backed очередь.
  3. Активная MCP-модель вызывает ide_provider_wait_request.
  4. Модель читает задачу, при необходимости использует file/git/command tools.
  5. Модель вызывает ide_provider_send_response.
  6. IDE получает OpenAI-compatible ответ.

Безопасность

  • Endpoint bind-ится только на 127.0.0.1; 0.0.0.0 и внешние hosts запрещены.
  • /v1/* требует локальный token; /health не раскрывает секреты.
  • Логи редактируют Authorization, X-API-Key, api_key, token, secret, password и idep_....
  • Endpoint state и очереди живут в gitignored temp/ide_provider_runtime/.
  • Локальные setup-конфиги плагина живут рядом с плагином в plugin.local.*.json и не попадают в Git/release archive.

Как выключить

  1. Откройте plugins\ide_provider.
  2. Запустите DISABLE.bat.
  3. Выберите тот scope, который включали: current или global.
  4. Перезапустите MCP.
